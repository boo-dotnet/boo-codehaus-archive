 Hans-Christian Holm

Map and zip are duplicated mostly for fun. They look a lot better in Boo than in C#, but I must say I never really understood why they are built-ins and not put under some appropriate namespace, like the System.Math.* functions are static methods and not built-ins. Is it to please the Python folks?

Operators can be nice to have as functions. They are used in Sum and Product.

I'm trying to sqeeze in more booisms at the moment, especially to make the methods/functions more general. I've come to love duck in Boo, and I'd like to have a duck-based functional library to start with. For functionalisms, I'd prefer things to be simple and general, rather than typed/specific and fast, to enable any kind of object to be treated in a similary manner. You could always add Boo.Lang.Useful.Functional.Generic or Boo.Lang.Useful.Functional.Macros later. (Unfortunately, there seems to be no way to specify namespaces when referring to macros at the moment. Is that going to change? Making a lot of macros for all kinds of functionalisms could be confusing if they all end up as "globals".)

You can't add methods directly under a namespace, they must be in a class. When you "def" something outside a class in Boo, it becomes a static method in a class named after the source file ("MyClassModule" etc). VB.NET does the same with modules.

## Description

Consider the following common case where an interface specifies a few optional methods:

interface IFoo:

 def Bar()

 def Baz() # optional

class FooBar(IFoo):

 def Bar():

 print "Bar"

I don't care about Baz so I should not be required to implement it

For the case above the compiler should:

1) warn that FooBar does not implement Baz

2) and since FooBar IS NOT DECLARED ABSTRACT the compiler should provide an empty stub for the required methods:

 def Baz():

 raise System.NotImplementedException()

### Avishay Lavie, 03/Jan/07 2:38 PM

I think this behavior shouldn't be the default, as it's contrary to the notion of interfaces.

Maybe if there was a special keyword to make the compiler add the stubs? For example, consider:

class FooBar(IFoo partial): 

 def Bar():

 print "Bar"

That way the "type does not implement interface member X" error can become "type does not implement interface member X; use the partial keyword to fill in missing members", but still remain an error (compare to "Member X hides inherited member by the same name. Use the new keyword to hide the original member"). That means that those who want the behavior can get it rather easily, while those who don't wish for it don't get it by mistake.

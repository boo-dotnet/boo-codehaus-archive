## Description

Currently when a member is shadowed, code has to actually use the member to get a (rather unfriendly) error : Ambiguous reference or an internal compiler error BOO-1014 

When the shadowed member is not used, it outputs without warning.

```
class Base:
 protected _d as int

class Test(Base):
 private _d as int

```

should issue :

BCE0090: Derived field 'Test._d' can not reduce the accessibility of 'Base._d' from 'protected' to 'private'.

(not sure about reusing 0090 or having a new error code for this)

```
class Base:
 protected _d as int

class Test(Base):
 private _d as double

```

should issue :

BCExxxx: Derived field 'Test._d' can not change signature of 'Base._d'

Actually both cases should issue warning instead:

BCWxxx: `Test._d' hides inherited member `Base._d'.

I think we should reuse 'override' keyword for explicit shadowing (since we do not have 'new' and 'override' is currently accepted yet ignored by the parser for field declarations)

Then the warning would be:

BCWxxx: `Test._d' hides inherited member `Base._d'. Use 'override' keyword if hiding was intended.

Makes sense?

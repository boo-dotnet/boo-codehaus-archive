### comment-38328

Hide

 Permalink

 Daniel Grunwald
 added a comment - 29/Apr/05 9:02 AM 

Fixed.

The problem was that the 'local variable' _b = value in the setter was used to resolve B instead of the field _b. 'value' resolved to the properties type, so we got a stack overflow.

Fields are now tried before the variable is tried to be resolved as local variable.

Peter Johanson found what appears to be the fix, while working on his MonoDevelop addin which suffered from the same problem. On line 96 in extras/sharpdevelop/boobinding/src/BooParser.cs, change ProcessMethodBodiesWithDuckTyping with StricterErrorChecking.

The error is because the inferred types of properties are not resolved until the ProcessMethodBodiesWithDuckTyping step, which had been removed.

So perhaps you guys could try that out and test it yourself to make sure, and contact Daniel Grunwald if it works, since he is the #Develop genius

## Description

Both SharpDevelop and Visual Studio .NET adds an ImageListStreamer object to the form's resource file each time you add an ImageList control (to display ToolBar icons, for example).

When the compiler tries to compile this resource file throws a System.Reflection.TargetInvocationException exception from the WriteResources() method of the Boo.Lang.Compiler.Resources.FileResource class.

### Hans-Christian Holm, 01/May/05 3:22 PM

I've tested my suggested changes now, and apparently, it works. But alas, only apparently. Some serious gotchas:

AddResourceFile only makes resources that link to files. This means that the files must be deployed along with the assembly, which is not what you may want.

AddResourceFile raises an exception if FileName contains a path.

SharpDevelop adds paths, therefore, it does not work in SharpDevelop.

I have found no way to solve this with .NET 1.1. There is only AssemblyBuilder.AddResourceFile for linked files, and ModuleBuilder.AddResource for name/value sets.

How does it work with C# and VB in Visual Studio, then? I haven't investigated that, but it may be with the help of al.exe, the (unmanaged) assembly linker that comes with MS.NET. al.exe can embed resources when creating assemblies from "module" files. I guess that's not an option with Boo, unless Boo could make module files, however that is done. I doubt it's feasible and that someone would care to do it.

But, fear not, .NET 2.0 has something that looks like a solution. In 2.0, there is a ModuleBuilder.DefineManifestResource method that takes a Stream as one of the parameters. I suggest replacing the current resource implementations with ModuleBuilder.DefineManifestResource whenever Boo takes the .NET 2.0 path.

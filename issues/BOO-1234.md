## Description

(reported by Dmitry)

Consider the following AST attribute that clones a class (and then add/change some members etc...) :

```
public class CloneClass (AbstractAstAttribute):
 public override def Apply(node as Node) as void:
 c = node as ClassDefinition
 raise "not a class" if not c
 c2 = c.Clone() as ClassDefinition
 c2.Name += '2'
 c.DeclaringType.Members.Add(c2)

//-------------------------------------------------------------------

[cloneClass]
class A:
 pass

a2 = A2()

```

Quite unintuitively (in this context) the cloning of an AST node also clones the typesystem bindings, and thus without ringing any bell it will bind "A2()" to "A" instead of the intended (and imho intuitive enough) "A2".

i.e:

```
Node 'A2' bound to 'test.A.constructor()'.
Type of expression 'A2()' bound to 'test.A'.
Type of expression 'a2' bound to 'test.A'.
Type of expression 'a2 = A2()' bound to 'test.A'

```

In that context of such an AST attribute, ClearTypeSystemBindings() would be handy, but it is internal on nodes, though inconsistenly it is public on NodeCollection (which does not really help in the use case above).

I think there should be a simple way to simply do a clone of the AST only, here are 3 potential solutions I think of :

1) move MacroCompiler.CleanClone to Node's template

Patch here: http://pastie.org/560398

2) move MacroCompiler.CleanClone to Node's template, rename it UnboundedClone()

3) make 
{Node}

.ClearTypeSystemBindings public

4) (1 or 2) and 3

Opinions? Ideas?

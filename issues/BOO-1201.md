## Description

I was coding today and realized, you know, I'm doing both the Enter/Exit in a try block pattern (lock) and Exit/Enter in a try block inside that.

For symmetry, if the lock keyword had an unlock keyword, that would be neat (admittedly, something you only need when writing multithreaded code, but for symmetry 

Then I could make a wait queue like

lock queue:

 while len(queue) &gt; 0:

 action = queue.Dequeue()

 unlock queue: action()

 Monitor.Wait(queue)

For reference, my original C# for this is 20 lines long (including many 
{ and }

, of course, but still). So unlock would map to (sorry I'm new to Boo so this may be inaccurate)

Monitor.Exit(queue)

try:

 action()

ensure:

 Monitor.Enter(queue)

...which is much uglier. Let me know what you think.

Actually you could go even further if you want:

```

macro processQueue(queueRef):
 yield [|
 lock $(queueRef):
 while len($(queueRef)) &gt; 0:
 action = $(queueRef).Dequeue()
 unlock $(queueRef): action()
 Monitor.Wait($(queueRef))
 |]

```

then just do:

```

processQueue queue

```

whenever you need to process a queue

I don't think it's common enough to warrant a built-in keyword (macro actually) on its own.

You can easily add 'unlock' in your project with a macro (built-in's 'lock' is actually a macro also) :

```

macro unlock(lockRef):
 yield [|
 Monitor.Exit($lockRef)
 try:
 $(unlock.Body)
 ensure:
 Monitor.Enter($lockRef)
 |]

```

btw you can surround text with "
{ code }

" (no spaces) for formatting.

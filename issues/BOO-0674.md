## Description

This patch improves how booc and the boo compiler load assembly references.

See mainly the Boo.Lang.Compiler.CompilerParameters.LoadAssembly method, which is adapted from the code used by mono's bmcs. I adapted for our error reporting scheme, and also made a change so it works on both .net 1.1 and .net 2. In .net 1.1, we use Assembly.LoadWithPartialName, in .net 2.0, we use Assembly.Load.

booc, booi, the InitializeNameResolutionService step, the BindNamespaces step, the BooCodeCompiler (codedom), and the CompilerParameters constructor have all been changed to use CompilerParameters.LoadAssembly.

This is necessary because of .net 1.1/2.0 issues for one. Referencing "System.Windows.Forms.dll" instead of "System.Windows.Forms" for example gave errors in .net 1.1 at least.

Also I noticed code that worked with C#'s codedom failed with boo's codedom because of assembly loading issues: http://www.codeproject.com/dotnet/DynamicCompileAndRun.asp

It works with the patch.

The assemblyresolve stuff was also removed from booc. I haven't tested on mono.

## Description

Currently, each compiler pipeline stands alone and our compiler pipeline model utilizes an inheritance model to propagate actions from one pipeline to another associated pipeline. This leads to very limited pipeline chaining. Instead, I propose that CompilerPipeline should also implement ICompilerStep so that it can be composed. This would allow for more elaborate and less restrictive chaining of pipelines:

```
Add(new CustomBeforeCompile());
Add(new Compile());
Add(new AfterCompile());

```

Perhaps make an explicit composite compiler step class, then clarifying the compile to file pipeline to something like:

```
Add(new Parse())
Add(new ResolveExpressions())
Add(new Compile())
Add(new EmitAssembly())
Add(new SaveAssembly())

```

where Parse, ResolveExpressions, Compile all become composite steps with their pipelines being more explicit about what steps are called?

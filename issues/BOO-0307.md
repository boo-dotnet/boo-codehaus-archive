## Description

We can use this to implement the options macro (BOO-273) among other features (see also BOO-300, BOO-128, BOO-114). For example:

#options Ducky, CaseInsensitive, RawArrayIndexing, Unchecked

This will involve altering the boo parser.

Other "potential" directives:

#define DEBUG

#undef DEBUG

#if TRUE

#elif DEBUG

#else

#endif

#region regionname

#endregion

#error error message

#warning disable/enable

#line 100

#include header.boo

We'd have to decide which built-in constants to define, such as:

TRUE

FALSE

NET_2_0

NET_1_1

MONO

WIN32

UNIX

I'd prefer all directives and constants be case-insensitive.

And to not interfere with people who prefer using hashes (#) for comments (like Python and shell scripts), we could perhaps do things like enforce no space between the hash and the directive ("#if" not "# if"), and/or have the parser simply ignore the line (treat it as a regular comment) if it is not a valid directive (like "#if x==y").

#if has to be processed by the tokenizer before the parser ever sees it. You can have invalid code in a false #if section yet the script will still compile because the parser never sees it. Also #if requires an #endif unlike a regular if. There is no indenting.

Using #options lets you set options for the whole file easier (put line at top of script, not at the bottom like assembly attributes), as well as set options at a micro level not possible with macros:

if (y and

 #options RawArrayIndexing

 x[i] and

 #options NormalArrayIndexing //or RawArrayIndexing=false

 z[i]):

 ...

Plus the main advantage I see is that #options will work in the interpreter, too. An assembly attribute for CaseInsensitive, for example, wouldn't work in the interpreter, since the parser only recognizes it if it is at the bottom of a script. You'd get errors before you even get to the assembly attribute.

Well another way to do it is to allow an "options" at the top of a script like VB:

Options RawArrayIndexing, Unchecked, CaseInsensitive

and the parser essentially translates that special case into an assembly-level AST attribute:

[assembly:Options(RawArrayIndexing:true, Unchecked:true, CaseInsensitive:true)]

And then for micro-level stuff we can add built-ins similar to typeof() (and how C# does it):

y = checked

unchecked

z = rawArrayIndexing(x[i])

This way would be easier to implement, but whichever way is fine with me.

## Description

I think it would be handy to be able to resolve between these 2 functions:

 public static bool InitX(string configFile, string xName, out string environmentName);

 public static bool InitX(string environmentName, string configFile, string xName);

At the moment, the compiler reports this as an ambiguous reference, no matter what type is passed in as the third parameter. I realise that this interface is not CLS-compliant, but it would be nice to use interfaces like this from Boo.

I'm familiar with compiler construction and am happy to make this change to the Boo source code myself. However, we need to answer these questions first :

I guess there's strictly 2

decisions:

1) Do we actually want Boo to provide a method of being able to resolve this specific type of ambiguous reference?

2) What would the syntax for doing this look like? Would it be as simple as:

string myString;

Accessors.InitX( "a", "b", out myString)

or would we make it a property of the type of the variable being passed in?

Just assign the task back to me with comments and I'll submit a patch (if we decide to go ahead with this change).

### Daniel Grunwald, 27/Apr/09 5:49 AM

I think you shouldn't introduce new syntax just to handle this special case.

The following would be a possible solution without having to introduce new syntax:

to call the first method

a as callable(string, string, out string) = Accessors.InitX

a("a", "b", myString)

#to call the second method

b as callable(string, string, string) = Accessors.InitX

b("a", "b", myString)

Does this work with Boo's current callables? Maybe the method-group to callable conversions needs to be adjusted to handle "ref" and "out".

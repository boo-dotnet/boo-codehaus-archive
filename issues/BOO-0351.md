## Description

Here's a quickie that perplexed me for a bit:

&gt;&gt;&gt; atoi = 
{ e as char | return cast(int, e) }

&gt;&gt;&gt; atoi(char(' ') )

32

&gt;&gt;&gt; toi = 
{ e as duck | return cast(int, e) }

&gt;&gt;&gt; toi(char(' ') )

System.Reflection.TargetInvocationException: Exception has been thrown by the target of an invocation. ---&gt; System.InvalidCastException: Specified cast is not valid.

 at Boo.Lang.Runtime.RuntimeServices.CheckNumericPromotion(Object value)

 at Boo.Lang.Runtime.RuntimeServices.UnboxInt32(Object value)

 at Input14Module.___closure1(Object e)

 at Input15Module.Main(String[] argv)

Although a duck, the underlying type is actually a char - so does it make sense for the cast to fail like that?

Comments, feed back?

### Arron Washington, 03/Jun/05 10:04 PM

To add more information to the original issue:

The situation that prompted me to bring this up was something like this:

 enum Measure:

 Pathetic = 32

 Weak

 Average

 Strong

 Superhero

 enum AttributeIndex:

 Str = 0

 Dex

 Wis

 Int

 toi = 
{ e as duck | return cast(int, e) }

 attributes = " !##"

 Strength = toi(attributes[toi(AttributeIndex.Str)])

 Wisdom = toi(attributes[toi(AttributeIndex.Wis)])

 Agility = toi(attributes[toi(AttributeIndex.Dex)])

 Intelligence = toi(attributes[toi(AttributeIndex.Int)])

Invalid cast error, of course. However, the odd part is:

 &gt;&gt;&gt; var as duck = 1

 1

 &gt;&gt;&gt; 1.GetType()

 System.Int32

 &gt;&gt;&gt; 

Although var is a duck variable, when you call "GetType()" the system correctly infers it as an integer.

It seems strange that a runtime exception is thrown with the basis of "the specified cast is invalid" if the underlying type of a duck-type is actually valid in the given circumstances.

## Description

Part bug, part yearning, request, its a love story that ended in tragedy:

class foo:

 virtual Sunny:

 get:

 return 1

class bar(foo):

 override Sunny:

 get:

 return 2

 def rock():

 print Sunny

 print super.Sunny

This code causes the compiler to believe that it is trying to invoke the overloaded method "rock" which really is not overloaded! That is wrong, BAD SUPER KEYWORD!

In reality we are merely trying to access base implementations of a particular member - in essence, "super" from anywhere else in the class. It would be nice to do this arbitrarily.

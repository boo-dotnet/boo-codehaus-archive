## Description

Currently, addins do not these members to code completion data:

1) AST Attributes, such as [getter] and [property]. These attributes are signaled by the example syntax, "PropertyAttribute" and have AbstractAstAttribute somewhere in their inheritance tree. 

2) AST macros, such as "print" and "unless". These macros are signaled by the example syntax, "PrintMacro," and have AbstractAstMacro somewhere in their inheritance tree.

3) Modules with static functions that are imported via the "import" syntax, ex "import Boo.Lang.Useful.IO" imports the contents of WalkModule, that contains static functions for traversing a directory tree. I believe they are marked with the [Module] attribute.

4) Classes with static functions imported via the "import" syntax, ex, "import System.Drawing.Color" imports the static members of the Color class into the current scope.

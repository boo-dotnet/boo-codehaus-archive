I had a look into this issue.

It stems from an optimization done in BooParser.cs, lines 183-184. The compiler step necessary for transforming variables declared in a conditional when casting is used doesn't occur when this optimization is used. Since they never go through VariableLookupVisitor, #develop doesn't even know these variables "exist."

Removing the optimizations on lines 183-184 resolves this issue. In the sample code below, #develop now recognizes "field" as a variable, and identifies its type correctly. Removing the optimizations also resolves BOO-629, variable scope. Specifically, I think "ProcessSharedLocals" has to always be run in order for these two issues to be resolved.

However, removing this optimization causes a bug! In the sample code below, "member" is no longer resolved to be a type of object. Rather, it is a suspicious question-mark .

It looks like ProcessSharedLocals is somehow the culprit – "field" won't be resolved if it isn't run, but if it is run "member" is resolved to the "error" type.

Hope this helps!

import System

import System.Reflection

for member in [1, 2, 3]:

 if field = member as FieldInfo:

 print field

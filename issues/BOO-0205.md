## Description

See the attached example. In a boo class (doesn't happen in C#), the first static method is 10 times slower to call than the others. I noticed this when defining arithmetic operators - the first one (op_addition) was 10 times slower than the others. Weird.

Example is attached.

Here is the class def:

class Test:

 static def nothing():

 pass

 static def nothing2():

 pass

 static def nothing3():

 pass

Here is output on my machine (doesn't depend on order of call, only order of definition):

Test.nothing2: 00:00:00.2303312

Test.nothing: 00:00:03.2546800

Test.nothing3: 00:00:00.1201728

I also see the problem, even if you change them to regular instance methods, or even if you add a constructor (after the other methods).

But, I only see it with booi. If I compile to an exe with booc, the times are all fast.

I noticed in C# with equivalent code, the times are all fast but only in release mode. In a debug version of the C# app, all methods run just as slow as the slow method in boo.

It appears to be something with .NET and the dynamically generated in-memory assembly. It could be it just isn't optimized when it is generated on the fly in memory.

## Description

See attached solution for example. There are two Boo projects in the solution. Project 1 defines an interface with an event. Project 2 defines a class that implements the interface. When the code is compiled, this error is thrown: 

An error occurred during the execution of the step 'Boo.Lang.Compiler.Steps.EmitAssembly': 'Method 'add_SweetEvent' in type 'InterfaceCompileError.Stubs.SweetStub' from assembly 'Stubs, Version=1.0.2856.0, Culture=neutral, PublicKeyToken=null' does not have an implementation.'. (BCE0011)

If we move the class file into the same project as the interface, compilation succeeds.

### Curtis Schlak, 15/Oct/08 1:46 PM

From trunk (revision 3049), I can reproduce this.

Contents of one.boo

namespace First

interface One:

  event DoIt as callable(One, string)

Contents of two.boo

namespace Second

class Two(First.One):

  event DoIt as callable(First.One, string)

I compile the first assembly with the command line

booc -t:library -o:First.dll one.boo

and all goes well. I attempt to compile the second assembly with the command line

booc -t:library -o:Second.dll -r:First.dll two.boo

and get the error message

Boo Compiler version 0.8.2.3038 (CLR v2.0.50727.3053)

BCE0011: An error occurred during the execution of the step 'Boo.Lang.Compiler.Steps.EmitAssembly': 'Method 'add_DoIt' in type 'Second.Two' from assembly 'Second, Version=0.0.0.0, Culture=neutral, PublicKeyToken=null' does not have an implementation.'.

Running booc with -vvv, we see that during the compilation phase, the Boo compiler assigns Two.DoIt the "callable" type CompilerGenerated.__Two_DoIt$callable0$4_19__. This clashes with the compiler-generated type for the interface One declared in First.dll whose DoIt event has type CompilerGenerated.__One_DoIt$callable0$4_19__.

## Description

When a static construct is placed in the wrong section of a class, the compiler doesn't seem to be able to handle type-inference. Placement of static methods and properties shouldn't have this effect.

See code example:

// - - - - -

class Bug:

 [property(Id)]

 _id = 0

 #Compiler error! BCE0022: Boo.Lang.Compiler.CompilerError: Cannot convert 'int' to 'unknown'

 /*

 static def Load():

 return Bug(Id: -1)

 */

 def constructor():

 pass

 override def ToString():

 return "Id: $
{self.Id}"

class NoBug:

 [property(Id)]

 _id = 0

 def constructor():

 pass

 override def ToString():

 return "Id: ${self.Id}

"

 #WORKS! - The only thing that's changes is code placement!

 static def Load():

 return NoBug(Id: -1)

nobug1 = NoBug(Id: 1)

nobug2 = NoBug(Id: 2)

nobug3 = NoBug.Load()

print nobug1, nobug2, nobug3

bug1 = Bug(Id: 1)

bug2 = Bug(Id: 2)

#bug3 = Bug.Load()

print bug1, bug2#, bug3

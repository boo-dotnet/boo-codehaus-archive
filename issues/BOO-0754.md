## Description

Examine this booish session, remembering that 0xF0000000 = 4026531840 when unsigned:

&gt;&gt;&gt; 0xF0000000

-268435456

&gt;&gt;&gt; 4026531840

ERROR: Error reading from 'input9': 'Value was either too large or too small for

 an Int32.'.

&gt;&gt;&gt; c as uint = 0xF0000000

-268435456

&gt;&gt;&gt; c.GetType()

System.OverflowException: Value was either too large or too small for a UInt32.

at System.Convert.ToUInt32(Int32 value)

at System.Int32.System.IConvertible.ToUInt32(IFormatProvider provider)

at Boo.Lang.Runtime.RuntimeServices.UnboxUInt32(Object value) in f:\Programmi

ng\Current\Boo\src\Boo.Lang\Runtime\RuntimeServices.cs:line 1738

at Input23Module.Main(String[] argv)

I'm not even sure how it managed to assign a negative number to "c", as its an unsigned variable...

This is actually two bugs. The first is that in BooParserBase.ParseIntegerLiteralExpression int.Parse allows the hex values it computes to overflow an integer:

&gt;&gt;&gt; int.Parse("F0000000", NumberStyles.HexNumber)

-268435456

I would assert that we should use uint.Parse and ulong.Parse to perform this step instead to fix this problem.

The second is that Boo does not error out when integer literals exceed variable bounds. That is, in booi you can happily write:

&gt;&gt;&gt; number as byte = -2

-2

&gt;&gt;&gt; number.ToString()

System.OverflowException: Value was either too large or too small for an unsigne

d byte.

&gt;&gt;&gt; number as byte = 1000

1000

&gt;&gt;&gt; number.ToString()

System.OverflowException: Value was either too large or too small for an unsigne

d byte.

When not using booi, the overflow is silent. That is, using booc:

a as uint = -2

b as byte = 1000

print a

print b

Gives this:

232

4294967294

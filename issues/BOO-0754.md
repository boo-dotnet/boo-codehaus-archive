This is actually two bugs. The first is that in BooParserBase.ParseIntegerLiteralExpression int.Parse allows the hex values it computes to overflow an integer:

&gt;&gt;&gt; int.Parse("F0000000", NumberStyles.HexNumber)

-268435456

I would assert that we should use uint.Parse and ulong.Parse to perform this step instead to fix this problem.

The second is that Boo does not error out when integer literals exceed variable bounds. That is, in booi you can happily write:

&gt;&gt;&gt; number as byte = -2

-2

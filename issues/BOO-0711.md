## Description

When bitwise operations are performed between non signed integer variable and a constant, the resulting type is widened, which is a very surprising and hard to spot behaviour:

```
a as short = 123456
b as uint = 123456
using writer = BinaryWriter(File.OpenWrite("test.dat")):
 writer.Write(a &amp; 0xFFFF); // uses BinaryWriter.Write(System.Int32) here!!!!
 writer.Write(b &amp; 0xFFFF); // uses BinaryWriter.Write(System.Int64) here!!!!

```

Propably it needs to guess the best type for a constant based on expression it is used in, instead of always giving out signed integer. This way it won't widen type to save bits which are simply not there.

## Description

The attribute mimics the way Visual C# 2005 handles resources (It generates a facade called &lt;MyResources&gt;.Designer.cs), and it gives you strong-named and strong-typed access to the resources at compile time.

Instead of typeing myResourceManager.GetString("ArgumentOutOfRangeException_Port");, you use MyResources.ArgumentOutOfRange_Port. Therefore, you won't have to debug your resource access at runtime.

The attribute gives you more power than Visual C# 2005's implementation in an IDE independent manner. Please read the documentation for each constructor in the file for more information.

The standard is to have:

/src/MyCompany.MyProject

/src/MyCompany.MyProject/Properties

/src/MyCompany.MyProject/Properties/AssemblyInfo.boo

/src/MyCompany.MyProject/Properties/MyResources.boo

/src/MyCompany.MyProject/Properties/MyCompany.MyProject.Properties.resources (.resx too)

/src/MyCompany.MyProject/Main.boo

In MyResources.boo:

namespace MyCompany.MyProject.Properties

[resourceFacade]

class MyResources:

. pass

In Main.boo:

namespace MyCompany.MyProject

import MyCompany.MyProject.Properties

....

raise ArgumentOutOfRangeException('port', MyResources.ArgumentOutOfRange_Port) unless IsPortValid(port)

....

No casting is required for any data stored in the resource file.

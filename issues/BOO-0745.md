## Description

In booish on win2k with any clr version a list comprehensions as a statement (without assignment) will produce a syntax error rather than the expected List return value.

e.g.:

&gt;&gt;&gt; alist = ['a','b','c']

['a', 'b', 'c']

&gt;&gt;&gt; [item for item in alist]

----------^

ERROR: Unexpected token: for.

----------------------------^

ERROR: Unexpected token: .

The same behavior is seen with the [item | item in alist] syntax.

List comprehensions with assignment, e.g. d=[item for item in alist], work correctly.

The easy workaround is not to use the compehension but to loop directly.

Looking into this issue, it's apparently not specific to the interpreter. Using the example from the similar issue BOO-970:

```

a = false
b = true
a and b

```

Results in the same error [BCE0043: Unexpected token: a.]

Using this example in booi gives you [BCE0034: Boo.Lang.CompileError: Expressions in statements must only be executed for their side-effects.] That error is only suppressed in the interpreter, possibly meaning the same parsing issue does exist in booc, but is masked by the error.

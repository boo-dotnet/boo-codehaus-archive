## Description

Currently when applied to a class, SingletonAttribute will cause the following FxCop warnings:

Error, Certainty 95, for StaticConstructorsShouldBePrivate

{

 Target : .cctor() (IntrospectionTargetMethodBase)

 Resolution : "Declare an explicit static constructor for 'SingletonClass+__Nested'."

 Help : http://www.gotdotnet.com/team/fxcop/docs/rules.aspx?version=1.35&amp;url=/Security/StaticConstructorsShouldBePrivate.html (String)

 Category : Microsoft.Security (String)

 CheckId : CA2121 (String)

 RuleFile : Security Rules (String)

 Info : "Non-private static constructors can cause unexpected 

 behaviors, particularly when executed multiple times. 

 This violation can occur if a type declares static 

 data but has not explicitly declared a static constructor.

 In this case, some compilers will generate an externally 

 visible static constructor."

 Fix Category : Breaking (FixCategories)

}

Warning, Certainty 75, for AvoidUninstantiatedInternalClasses

{

 Target : SingletonClass+__Nested (IntrospectionTargetType)

 Resolution : "'SingletonClass+__Nested' is an internal 

 class that is apparently never instantiated. If so, 

 remove the code from the assembly. If this class is 

 intended to contain only static methods, consider adding 

 a private constructor to prevent the compiler from 

 generating a default constructor."

 Help : http://www.gotdotnet.com/team/fxcop/docs/rules.aspx?version=1.35&amp;url=/Performance/AvoidUninstantiatedInternalClasses.html (String)

 Category : Microsoft.Performance (String)

 CheckId : CA1812 (String)

 RuleFile : Performance Rules (String)

 Info : "An internal class was detected that is apparently never 

 instantiated. This rule does not attempt to detect 

 late-bound creation and will generate false positives 

 if instances of a type are only created in this way 

 (for example, by means of Activator.CreateInstance 

 or by passing the type as an argument to a TypeConverter 

 constructor)."

 Fix Category : NonBreaking (FixCategories)

}

Fixed in the attached patch. As well, the generated property and nested class are now decorated with CompilerGenerated attributes.

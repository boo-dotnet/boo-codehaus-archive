## Description

We've been discussing some possible syntaxes for closures but I'd like to gather some more opinions on this matter.

The new syntax must blend in with the current syntactic framework. Some of the values that have been driving the design are simplicity, terseness, python-likeness 

I'd rather avoid introducing new keywords if possible.

The syntax should ideally allow ruby-like block to method passing.

The current candidate syntax reuses the callable keyword:

anonymous method with a single parameter

button.Click += callable(sender):

 print("$
{sender}

 was clicked!")

no parameters

button.Click += callable:

 print("clicked!")

block to method

result = [1, 2, 3, 4].Collect() callable(item as int):

 return 0 == item % 2

assert [2, 4] == result

could also be written

predicate = callable(item as int):

 return 0 == item % 2

assert [2, 4] == [1, 2, 3, 4].Collect(predicate)

A lambda expression like syntax could be supported as well:

 result = [1, 2, 3, 4].Collect(callable(item as int): 0 == item % 2)

 spam = sketches.Find(callable(s as Sketch): "spam" == s.Name)

thoughts?

Stuart got a point. I'm not sure I like the &lt;&gt; thing but yes, there should be an alternative syntax to allow one liners as well as passing closures as arguments to functions.

Let me think out loud here, what if we allowed an alternative block syntax? One that was not whitespace sensitive?

Braces would seem like a natural choice since they are already in use in lots of languages.

Under this new syntax, this:

 if foo &gt; bar:

 print(foo)

 print(bar)

could be also written like this:

 if foo &gt; bar 
{ print(foo); print(bar) }

or like this:

 if foo &gt; bar 
{
 print("foo");
 print("bar");
 }

In other words:

button.Click += callable(sender):

 print("$
{sender} was clicked!")

could be also written like this:

button.Click += callable(sender) { print("${sender}

 clicked!") }

Thoughts?

## Description

After commit 2936 to fix BOO-1009, which works really well, mind you, my code failed to build because of explicitly overridden interfaces in child classes. Previously, booc would compile without error:

```
interface IFace:
 Prop:
 get:
 pass
class Expl(IFace):
 Prop as string:
 get:
 return "MOO"
 IFace.Prop:
 get:
 return true
```

Of course, before revision 2936, it wouldn't behave correctly, but I was looking for the side effect. Now that C. Vivier has fixed the problem, the previous code will not compile with trunk. This type of behaviour is required for multiple interface inheritance with clashing property names, which I have found on some third-party work that I've completed. For example:

```
/* In third-party assemblies */
public interface IInterface1 {
 string Property {get; set;}
}
public interface IInterface2 {
 bool Property {get;}
}

# In Boo consumer code...
class ExplicitImplementation(IInterface1, IInterface2):
 Property:
 get:
 return b
 set:
 b = value
 
 IInterface1.Property:
 get:
 return s
 set:
 s = value

 private b as bool
 private s as string
```

The attached patch file and test cases modify and exercise the compiler to allow for the above cases. The tests cases belong in trunk/tests/testcases/regression directory similar to the BOO-1009. nant test runs with no exceptions.

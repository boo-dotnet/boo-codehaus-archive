## Description

The following works as intended; it extends a generic that has a where caluse

```
# case 1, generic where clause specifies an external type
interface MyExternalReferencingGeneric[of I(string)]:
 pass

interface MyExternalEncapulatingGeneric[of I(string), L(MyExternalReferencingGeneric of I)]:
 pass
```

If, however, instead of a "derivation type" of an externally defined string, we attempt to build and derive from a generic whose where clause is internally defined, things go awry. The following is a recitation of the above, with string replaced by MyClass:

```
# case 2, generic where clause specifies an internal type
interface MyClass:
 pass

interface MyInternalReferencingGeneric[of I(MyClass)]:
 pass

# broken:
# BCE0149: The type 'I' must derive from 'com.voodoowarez.chain.MyClass' in order to substitute the generic parameter 'I' in 'com.voodoowarez.chain.MyInternalReferencingGeneric[of I]'.
interface MyInternalEncapsulatingGeneric[of I(MyClass), L(MyInternalReferencingGeneric of I)]:
 pass
```

The type information of "I" in this case is lost in MyInternalEncapsulatingGeneric's definition of L.

The loss of type information is also apparent in Nested classes:

```
interface MyClass:
 pass

interface MyInternalReferencingGeneric[of I(MyClass)]:
 pass

class Foo[of I(MyClass)]:
 class Bar:
 # Broken:
 # BCE0149: The type 'I' must derive from 'MyClass' in order to substitute the generic parameter 'I' in 'MyInternalReferencingGeneric[of I]'.
 intRef as MyInternalReferencingGeneric[of I]
```

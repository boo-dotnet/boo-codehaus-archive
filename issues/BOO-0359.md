## Description

using w = 3:

 print w

fails with: ERROR: 'System.Int32' is a value type. The 'as' operator can only be used with reference types.

solution? the using macro should work around value types to not try 'as'.

Here is an instance where 'using' on a value type is nice: when refering to the returned value of a long function name:

begin ##

def LongWindedFunctionName() as int:

 return 2

using w as LongWindedFunctionName():

 print w, 2*w, 4*w

end ##

This can of course work just as well by saying:

w = LongWindedFuntionName()

print w,2*w,4*w

But this pollutes the enclosing namespace with 'w'.

Perhaps there is no way around this - i.e. that it is impossible to define stack variables in a local sub-scope. I would be a little surprised, but I don't know the details of how .net works.

There is a problem either way: it is surprising that "using" does not work for value types. So if "using" can not be changed to support value types in the expected manner, the error message should be changed so that people understand that the problem is because it is a value type (as opposed to the current message which exposes the internal implementation's use of 'as', i think).

ps - i absolutely love boo. i'm not trying to nitpick here, but rather to report bugs as i come across them so that boo gets the glossy shine it rightfully deserves.

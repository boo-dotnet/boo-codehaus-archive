## Description

When there is a boo.lang.compiler.dll in the gac and one next to booc.exe, booc will always use the one in gac, even if it is out of date.

This shows up as an error only in rare cases though, like when you reference boo.lang.compiler.dll with a path and get the error: RequiredAttribute is not a valid attribute.

Below is more info about how to reproduce that particular error, but it isn't that important.

A fix for this is in the comment below.

I can reproduce this error in one obscure case. The same error happens in older versions of boo too (so not my fault .

It only happens when you have boo dlls in the gac AND you reference boo.lang.compiler.dll with a path.

It's not that important, since basically we can just tell people not to reference boo.lang.compiler (it is already referenced by compiler anyway).

This is in .net 1.1.

First, put any version of boo dlls in C:\windows\assembly\ (boo.lang.dll, boo.lang.compiler.dll, boo.lang.parser.dll).

Then from the root boo folder, run:

bin\booc.exe -o:bin\mybooi.exe -t:exe src\booi\booi.boo

--&gt;works fine

bin\booc.exe -o:bin\mybooi.exe -t:exe src\booi\booi.boo -r:Boo.Lang.Compiler

--&gt;works fine, reference boo.lang.compiler.dll from gac

bin\booc.exe -o:bin\mybooi.exe -t:exe src\booi\booi.boo -r:Boo.Lang.Compiler.dll

--&gt;works fine (but not in prev. versions of boo, that was fixed)

Now:

bin\booc.exe -o:bin\mybooi.exe -t:exe src\booi\booi.boo -r:bin\Boo.Lang.Compiler.dll

--&gt;Error RequiredAttribute is not a valid attribute

Just adding that r:bin\Boo.Lang.Compiler.dll makes booc.exe load the Boo.Lang.Compiler.dll from the GAC instead of the Boo.Lang.Compiler.dll next to it. This happens before the "-r" option is even looked at by booc's ParseOptions. It happens right as the booc\App.cs&gt;Run() method is loaded and called.

This is because before Run is called, .net loads the types of the locals used, which include CompilerParameters and BooCompiler.

I'm not sure why this is happening though. Perhaps the .net runtime pays attention to any -r: option passed to an exe.

Anyway, as I said the same bug existed in older versions of boo too, and the workaround is simple.

OK, this is really a larger issue. When there is a boo.lang.compiler.dll next to booc.exe and in the GAC, the one in GAC will always be loaded, even if it is out of date.

The easiest solution I could find that works is to simply update the assembly version in the sources whenever you build a new version.

Here are the changes I made to the default.build file. I could also change it so the version is updated everytime you rebuild. Let me know if this is ok to check in.

I tested and even if 0.7.6.2127 is in gac and 0.7.6.2128 is next to booc, it will load the right one (the one next to booc).

In default.build, I changed the boo.assembly.version property to this:

 &lt;property name="boo.assembly.version" value="$
{boo.major.minor.release.version}

.$
{boo.svn.revision}

" /&gt;

And here is my version of the update-assembly-attributes task, it no longer depends on svn or other boo tasks.

 &lt;target name="update-assembly-attributes"&gt;

 &lt;loadtasks assembly="bin/Boo.NAnt.Tasks.dll" /&gt;

 &lt;echo message="Updating assembly versions to: $
{boo.assembly.version}" /&gt; 

 &lt;boo&gt;

 import System.IO

 fname = "src/Boo.Lang/Builtins.cs"

 using sr=StreamReader(fname):

 builtins = sr.ReadToEnd()

 version = Project.Properties["boo.version"]

 newBuiltins = @/new System.Version(".+")/.Replace(builtins, "new System.Version(\"${version}\")")

 if builtins != newBuiltins:

 print fname

 using sw=StreamWriter(fname):

 sw.Write(newBuiltins) 

 &lt;/boo&gt;

 &lt;updateAssemblyVersion

 version="${boo.assembly.version}

"&gt;

 &lt;fileset basedir="src"&gt;

 &lt;include name="**/AssemblyInfo.cs" /&gt;

 &lt;include name="**/AssemblyInfo.boo" /&gt;

 &lt;/fileset&gt;

 &lt;fileset basedir="extras"&gt;

 &lt;include name="**/AssemblyInfo.boo" /&gt;

 &lt;/fileset&gt;

 &lt;/updateAssemblyVersion&gt;

 &lt;updateAssemblyVersion

 &lt;fileset basedir="src"&gt;

 &lt;include name="**/AssemblyInfo.cs" /&gt;

 &lt;include name="**/AssemblyInfo.boo" /&gt;

 &lt;/fileset&gt;

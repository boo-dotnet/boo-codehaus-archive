## Description

When there is a boo.lang.compiler.dll in the gac and one next to booc.exe, booc will always use the one in gac, even if it is out of date.

This shows up as an error only in rare cases though, like when you reference boo.lang.compiler.dll with a path and get the error: RequiredAttribute is not a valid attribute.

Below is more info about how to reproduce that particular error, but it isn't that important.

A fix for this is in the comment below.

I can reproduce this error in one obscure case. The same error happens in older versions of boo too (so not my fault .

It only happens when you have boo dlls in the gac AND you reference boo.lang.compiler.dll with a path.

It's not that important, since basically we can just tell people not to reference boo.lang.compiler (it is already referenced by compiler anyway).

This is in .net 1.1.

First, put any version of boo dlls in C:\windows\assembly\ (boo.lang.dll, boo.lang.compiler.dll, boo.lang.parser.dll).

Then from the root boo folder, run:

bin\booc.exe -o:bin\mybooi.exe -t:exe src\booi\booi.boo

OK, this is really a larger issue. When there is a boo.lang.compiler.dll next to booc.exe and in the GAC, the one in GAC will always be loaded, even if it is out of date.

The easiest solution I could find that works is to simply update the assembly version in the sources whenever you build a new version.

Here are the changes I made to the default.build file. I could also change it so the version is updated everytime you rebuild. Let me know if this is ok to check in.

I tested and even if 0.7.6.2127 is in gac and 0.7.6.2128 is next to booc, it will load the right one (the one next to booc).

In default.build, I changed the boo.assembly.version property to this:

 &lt;property name="boo.assembly.version" value="$

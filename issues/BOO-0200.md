## Description

Expressions involving unsigneds are not promoting correctly. Also, you cannot declare/use a signed byte in boo.

_byte as byte = 2 

_short as short = 2 

_int as int = 2 

_long as long = 2 

_single as single = 2.2 

_double as double = 2.2 

//_sbyte as sbyte = 2 

_ushort as ushort = 2 

_uint as uint = 2 

_ulong as ulong = 2 

print ((_byte + _ulong).GetType()) 

print ((_short + _uint).GetType()) 

print ((_short + _ulong).GetType()) 

print ((_int + _ulong).GetType()) 

print ((_ushort + _ulong).GetType()) 

print ((_uint + _ulong).GetType()) 

print ((_ulong + _ulong).GetType()) 

produces: 

System.Byte 

System.Int16 

System.Int16 

System.Int32 

System.UInt16 

System.UInt32 

System.UInt64

### Bill Wood, 05/Dec/04 12:57 PM

Ignore previous "Types.cs" attachment. This attachment contains all diffs for "Types.cs", "TypeSystemServices.cs", and "EmitAssembly.cs" to implement the sbyte type and fix numeric promotions.

Rodrigo please read my comments in the source files. There are several issues you should look at.

1) should ulong types combined with signed types return an error per the C# spec or should they return a long? The code would have to be refactored to return a compile-time error.

 Pros for compile-time error:

 Adheres to C# spec

 No type is big enough to hold result of ulong + &lt;signedType&gt;

 Cons for compile-time error:

 Code would need refactoring

 Couldn't do this (unless constant "1" was converted to ulong by boo first):

 ul as ulong = 0

 ul = ul + 1 // would need to say: ul = ul + cast(ulong, 1)

2) should all unsigned ints be considered as "IsIntegerNumber" so they can participate in "|" and "&amp;" operations? The byte type was already considered an IsIntegerNumber even though its unsigned.

3) should byte be considered an "IsUnsignedNumber"?

4) I changed the conversion op for bytes to Conv_U1 from Conv_I1 as byte is unsigned

We cannot simply Reset the RangeEnumerator because we don't know if the first GetEnumerator() consumer is done.

Someone might do: r = range(3); z = zip(r, r)

Every GetEnumerator call must return a new enumerator. If you want to save allocations by combining the Enumerable with the Enumerator, you can "return this;" for the first GetEnumerator() call only, subsequent calls must create new objects.

I believe both should not reset automatically, they wouln't be a "standard"/verifiable implementation of IEnumerator :

"If MoveNext passes the end of the collection, the enumerator is positioned after the last element in the collection and MoveNext returns false. When the enumerator is at this position, subsequent calls to MoveNext also return false. If the last call to MoveNext returned false, calling Current throws an exception. To set Current to the first element of the collection again, you can call Reset followed by MoveNext."

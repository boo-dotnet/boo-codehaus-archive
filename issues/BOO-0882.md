## Description

The following code results in Error BCE0055: Internal compiler error: Invalid entity type for mapping: Ambiguous.. 

```
import System
import System.Collections.ObjectModel

class Item:
 public Key as string
 public Value as string

class ItemList(KeyedCollection[of string, Item]):
 override def GetKeyForItem(item as Item) as string:
 return item.Key

list = ItemList()
list.Add(Item(Key:'foo Key',Value:'foo Value'))
list.Add(Item(Key:'bar Key',Value:'bar Value'))

print list['foo Key'].Value 

```

I think this is a different problem: namely, the compiler cannot disambiguate between different members with similar signatures, where one of them was created through generic parameter substitution and one wasn't. I believe the same problem would arise if the indexed properties will be converted to methods; thus:

```

class Class[of T]:
 def Method(arg as int):
 return "Non Generic"

 def Method(arg as T):
 return "Generic"

ci = Class[of int]()
print ci.Method(42)

```

According to the C# spec, in these cases the member that is "the least generic" should be chosen. We currently have the framework to do this in CallableResolutionService but it was never implemented, and I'm not sure indexed properties ever go through the CallableResolutionService.

The problem has to do with self-indexers on generic types not being mapped correctly when they are ambiguous. 

The following testcase reproduces the problem:

```

class Class[of T]:
 self[arg as int]:
 get: return "Non Generic"

 self[arg as T]:
 get: return "Generic"

c = Class[of string]()
print c["foo"]

```

The generic mapping is passed an Ambiguous entity, which it cannot map. 

Changing the self-indexer to a method or an indexed property makes the code compile.

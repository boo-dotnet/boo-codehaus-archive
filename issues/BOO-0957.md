## Description

Moreover the autocompletion/documentation/helper possibilities of IReflectiveQuackFu, it could be nice to add some compile-time checking feature to quack types.

We'd have an abstract class CheckedQuackFu(IReflectiveQuackFu) defining static method CheckedQuackGetMembers(Type), returning IEnumerable[of QuackFuMember] like IReflectiveQuackFu.QuackGetMembers()

When a type within the compile units inherits this class (thus it is a quack type), a new compiler step CheckQuackFuMembersStep would be added after EmitAssembly.

As a use-case let's imagine some ORM using quack-fu to generate queries :

(pseudo-code)

class QuackFuORM(CheckedQuackFu):

 ... quack get/set/invoke implementation here...

 def CheckedQuackGetMembers(type as Type) as IEnumerable[of QuackFuMember]:

 for p in type.GetProperties():

 yield QuackFuMember(Name: "FindBy$
{p.Name}

", Kind: QuackFuMemberKind.Method)

class User(QuackFuORM):

 Name as string

the following call would of course compile fine and generate a valid query :

User().FindByName("boouser")

the following would not compile fine since the member is not reflected (and for good reason since it would gen. an invalid query anyway) :

User().FindByNonsense("boouser") 

Thoughts?
